# 企鹅号 ixBrowser 自动发布 Skill 设计

## 1. 目标

把固定的企鹅号文章发布流程做成一个可复用 skill。

用户发出命令后，skill 自动：

1. 按 ixBrowser 固定窗口编号依次打开目标窗口。
2. 进入企鹅号文章发布页。
3. 为每个窗口发布 1 篇文章。
4. 自动完成标题、视频、视频封面、文章配图、文章封面设置。
5. 在开发模式下停在发布按钮前，等待确认。
6. 返回逐窗口的执行结果。

第一版只支持企鹅号文章发布，不做多平台通用框架。

## 2. 用户使用方式

### 2.1 命令格式

- `/发企鹅号 3窗口`
- `/发企鹅号 1-5窗口`

### 2.2 命令语义

- 命令中的数字直接对应 ixBrowser 固定窗口编号。
- 区间命令表示按编号顺序依次处理。
- 同一轮任务中，每个窗口发布 1 篇文章。

## 3. 文章发布类型

本 skill 只处理以下固定类型：

- 文章标题
- 无文字正文
- 插入 1 个视频
- 为该视频设置 1 张本地视频封面
- 插入 2 张站内图片素材作为文章配图
- 设置 1 张站内图片素材作为文章封面

不支持纯视频发布。

## 4. 素材目录

固定使用一个根目录，例如 `企鹅号发布/`。

目录结构：

- `企鹅号发布/videos/`
- `企鹅号发布/video-covers/`
- `企鹅号发布/logs/`

### 4.1 videos

存放待发布视频。

规则：

- 每个窗口每次消耗 1 个视频文件。
- 视频文件名去掉扩展名后，直接作为文章标题。
- 文件名中的 emoji 原样保留。
- 只有确认发布成功后才删除视频。
- 失败时不删除，留待下次重试。

示例：

- `亲爱的，这些话我必须对你说，你听完好吗？🥺.mp4`

对应文章标题：

- `亲爱的，这些话我必须对你说，你听完好吗？🥺`

### 4.2 video-covers

存放本地视频封面图。

规则：

- 每篇文章随机选 1 张。
- 使用后不删除。
- 允许循环复用。

### 4.3 logs

存放执行日志和结果记录。

至少记录：

- 执行时间
- 命令原文
- 窗口编号
- 视频文件名
- 生成标题
- 选中的视频封面文件
- 执行状态
- 失败原因

## 5. 站内固定素材规则

企鹅号“我的图片素材”中长期保持 3 张固定图片：

1. 文章配图 1
2. 文章配图 2
3. 文章封面图

skill 不管理站内素材库内容本身，只按固定顺序使用：

1. 先插入素材 1
2. 再插入素材 2
3. 再把素材 3 设为文章封面

即使以后更换素材，也必须继续维持“素材库固定有 3 张图，且顺序不变”的约束。

## 6. 执行模式

### 6.1 开发模式

默认模式。

规则：

- 全程可见操作
- 自动跑到发布按钮前停止
- 不自动点击发布
- 不删除视频文件
- 返回“已完成到待发布”状态

### 6.2 正式自动发布模式

稳定后可切换。

规则：

- 自动点击发布
- 只有平台明确反馈发布成功后，才删除视频文件
- 若发布失败，保留视频文件

第一版实现时必须先以开发模式为默认行为。

## 7. 执行顺序

同一条命令内严格串行，不并行。

例如 `/发企鹅号 1-5窗口` 的执行顺序为：

1. 窗口 1
2. 窗口 2
3. 窗口 3
4. 窗口 4
5. 窗口 5

原因：

- 更稳
- 更容易观察页面变化
- 更容易定位失败原因
- 避免多个窗口同时抢占素材或上传资源

## 8. 每个窗口的执行流程

对单个窗口，流程固定为：

1. 调 ixBrowser 本地 API 打开指定窗口。
2. 通过 Playwright/CDP 接管已打开的 ixBrowser 窗口。
3. 打开企鹅号文章发布页。
4. 从 `videos/` 中分配 1 个尚未被本轮其他窗口占用的视频。
5. 取视频文件名去扩展名后的内容作为文章标题。
6. 上传视频。
7. 从 `video-covers/` 中随机选择 1 张图作为视频封面。
8. 插入站内素材库中的第 1 张文章配图。
9. 插入站内素材库中的第 2 张文章配图。
10. 把站内素材库中的第 3 张图设置为文章封面。
11. 检查标题、视频、视频封面、配图、文章封面是否都已到位。
12. 若为开发模式，则停在发布按钮前。
13. 若为正式自动发布模式，则点击发布并等待成功结果。

## 9. 素材分配规则

一次命令开始时，先为每个窗口分配不重复视频。

例如：

- 命令：`/发企鹅号 1-3窗口`
- 本轮需预留 3 个不同视频

这样可以避免：

- 同一轮多个窗口发同一个视频
- 中途失败后重复抽取导致结果混乱

视频封面图不需要唯一，可重复使用。

## 10. 结果反馈

执行结束后，向用户返回逐窗口结果。

示例：

- `1窗口：已完成，停在发布前`
- `2窗口：失败，视频上传超时`
- `3窗口：已完成，停在发布前`

同时补充关键信息：

- 使用的视频文件名
- 使用的视频封面图文件名
- 是否进入待发布状态

## 11. 失败处理

### 11.1 单窗口失败

- 记录失败原因
- 保留该视频文件
- 继续执行后续窗口

### 11.2 页面校验失败

如果以下任一关键项缺失，则视为未完成：

- 标题未填入
- 视频未上传完成
- 视频封面未设置完成
- 2 张文章配图未插入完成
- 文章封面未设置完成

此时：

- 不进入发布动作
- 记录失败
- 保留视频

### 11.3 发布失败

如果正式自动发布模式下点击发布后失败：

- 不删除视频
- 记录平台错误信息或页面状态
- 继续后续窗口

## 12. 技术路线

采用：

- ixBrowser Local API
- Playwright/CDP 接管窗口

原因：

1. ixBrowser 官方支持本地 API 打开窗口并交给自动化框架继续控制。
2. Playwright/CDP 适合复杂网页交互，较适合处理上传、弹窗、富编辑器、异步状态等场景。
3. 后续页面改版时，维护成本低于纯坐标点击式方案。

第一版目标是专用、稳定、可见，不追求通用任务平台。

## 13. 配置设计

第一版建议使用单独配置文件管理：

- ixBrowser API 地址
- 发布页 URL
- 根素材目录
- 默认运行模式
- 固定站内素材顺序规则

不把这些配置硬编码到 skill 文本中。

## 14. 非目标

第一版不做以下内容：

- 多平台通用发布
- 并行多窗口发布
- 自动维护企鹅号站内素材库
- 自动扫码登录
- 自动生成标题文案
- 自动写正文文本

## 15. 验证要求

实现完成后，至少验证：

1. 能按窗口编号正确打开 ixBrowser 目标窗口。
2. 能进入企鹅号文章发布页。
3. 能正确读取视频文件名并写入标题，包含 emoji。
4. 能成功上传视频。
5. 能成功设置本地视频封面。
6. 能按顺序插入 2 张站内配图。
7. 能成功设置站内文章封面。
8. 开发模式下能稳定停在发布按钮前。
9. 成功前不删除视频。
10. 失败后保留视频并记录日志。

## 16. 风险与约束

主要风险：

1. 企鹅号页面结构变化会导致定位失效。
2. 上传、封面裁剪、富文本插入可能存在异步状态，需要等待与重试。
3. ixBrowser API 权限、端口或 profile 状态异常会导致窗口无法接管。

约束：

1. 用户需提前在 ixBrowser 中登录对应账号。
2. 用户需提前维护好企鹅号站内素材库的 3 张固定图片。
3. 用户需保证 `videos/` 与 `video-covers/` 目录中存在可用文件。

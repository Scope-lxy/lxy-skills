# 重命名标题

## 总则

先读 `references/title-writing-principles.md`。用用户指定版本的案例校准说话的直接程度、亲密感、句子节奏和情绪浓度。可以借用其中贴合素材的自然用词和短表达，但不要照抄完整标题或批量套用同一个句式。允许从字幕提炼参考库未覆盖的任何情感表达。

每份素材只生成一个标题。若用户没有指定“暧昧版、祝福版、急迫版”中的一种，先询问版本，不要自动选择。

默认目录：

- 字幕：`%USERPROFILE%\Desktop\合成视频\字幕`
- 视频和封面：`%USERPROFILE%\Desktop\企鹅号发布\videos`

用户提供其他目录时使用用户目录。

## 工作流

### 1. 只读扫描

从本 Skill 目录执行：

```powershell
python scripts/media_title_batch.py scan
```

需要自定义目录时传入 `--subtitle-dir` 和 `--media-dir`。

只处理状态为 `ok` 的项目。视频、字幕或 `_cover` 封面缺少、重复或无法解析时，跳过该组，并在标题表后报告错误。不要猜测相似文件名，不要只处理三件套中的一部分。

使用扫描结果中的：

- `short_name` 作为“原文件（缩写）”，它是原标题的前 10 个字符。
- `sections.opening`、`sections.lyrics`、`sections.ending` 和 `full_text` 理解内容。
- `original_base` 作为后续改名的内部对应键，不要在确认表中完整展示。

### 2. 分析并原创标题

逐份素材完成：

1. 独立理解字幕，不受参考库关键词覆盖范围限制。
2. 提炼 2–3 个具体情感关键词。
3. 按用户指定版本，从这份字幕的感情核心出发写出初稿。
4. 强制进行一次口吻复写：把初稿改成中年男主播会自然地对一位具体女性说的话，去掉书面化、概念解释、生硬比喻和刻意拔高。
5. 检查标题是在直接“对她说”，而不是站在旁边解释两人的感情。暧昧版必须把爱意或难以割舍的关系说在主句里，让她不看视频也能听出“他爱她、放不下她、在等她或想守着她”；只有安慰、鼓励、惦记或泛泛温暖不算暧昧。
6. 朗读标题；若不像一条真诚、自然的私下消息，继续重写。然后将标题控制在 20–30 字，并执行对应称呼规则。
7. 避免同批标题使用相同核心句式或长片段；轮换句子起势、具体感受和关系动作，但不要为了求不同而制造别扭表达。

不要为了批量速度复用模板。可以借用 `references/title-library.tsv` 和口吻校准案例中贴合素材的用词、短表达与说话方式，但不要照抄完整标题，也不要在同一批次反复套用同一个核心句式。

### 3. 校验标题

在临时目录创建 UTF-8 JSON 计划，不要把它保存到素材目录。格式：

```json
{
  "style": "急迫版",
  "subtitle_dir": "C:\\Users\\LXYou\\Desktop\\合成视频\\字幕",
  "media_dir": "C:\\Users\\LXYou\\Desktop\\企鹅号发布\\videos",
  "items": [
    {
      "original_base": "扫描得到的完整原文件名，不含扩展名",
      "title": "准备展示的完整标题"
    }
  ]
}
```

执行：

```powershell
python scripts/media_title_batch.py validate --plan <临时计划.json>
```

修正所有 `errors`。检查 `warnings` 中的批内相似和参考库近似项；存在明显套句时重写，再次校验。相似度检查只防止照抄和雷同，不限制新关键词或新情绪。

### 4. 展示确认表

完整展示所有标题，不截断标题列。只使用以下四列：

| 序号 | 原文件（缩写） | 关键词 | 最终推荐标题 |
|---|---|---|---|

在表后单独列出扫描时跳过的项目和原因。等待用户确认或逐条修改。用户未明确确认当前批次前，不得运行真实改名。

### 5. 确认后改名

将用户修改后的标题写回临时计划并重新校验。先执行只读预检：

```powershell
python scripts/media_title_batch.py rename --plan <临时计划.json> --dry-run
```

检查预检结果后，再执行：

```powershell
python scripts/media_title_batch.py rename --plan <临时计划.json>
```

脚本按组同时改名：

- `原标题.srt` -> `新标题.srt`
- `原标题.mp4` -> `新标题.mp4`
- `原标题_cover.jpg` -> `新标题_cover.jpg`

保留封面原扩展名。每组三件套使用临时文件名完成事务改名；任一步失败时尝试回滚该组。缺失文件或目标冲突时跳过并报告，继续处理其他有效组。

完成后报告成功数量、跳过数量和具体错误。删除临时计划，不额外保存新旧文件名记录。

## 安全边界

- 把扫描、校验和 `--dry-run` 视为只读操作。
- 把不带 `--dry-run` 的 `rename` 视为不可提前执行的修改操作。
- 不修改字幕内容、视频内容、封面内容或标题参考库。
- 不覆盖现有目标文件。
- 不静默清洗用户已确认的标题；校验失败时先修正并重新确认。

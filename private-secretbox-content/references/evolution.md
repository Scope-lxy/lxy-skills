# 反馈演进记录

技能要在真实审稿中逐步变好，但每条新规则都必须可追溯。收到反馈时按以下顺序处理：

1. 判断是单条修订、当前批次修订，还是长期偏好。只有用户明确说“以后都”“固定”“默认”才写成长期规则。
2. 将原话改成一个可检查的规则，包含适用范围和例外。例如“标题太怪”应记录为“音频标题使用自然口语断句，避免两个抽象名词硬拼成诗句；仅适用于标题，不限制正文”。
3. 先重写当前受影响条目，再在下一批应用规则；不凭空改写历史交付物。
4. 记录版本、日期、触发反馈、采取的规则和验证方式。

## 日志模板

技能目录中的 `feedback-log.md` 已提供初始记录，后续按以下格式追加版本条目：

```markdown
# Feedback Log

## v0.1 - 2026-08-31
- 反馈：
- 规则：
- 适用：
- 验证：
```

若用户没有授权修改技能目录，就在回复中给出同样四行的“建议新增规则”，等待确认后再落盘。规则发生冲突时，以用户最新、范围更明确的指令为准，并注明覆盖旧规则。
